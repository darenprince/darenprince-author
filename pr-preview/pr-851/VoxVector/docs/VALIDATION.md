# VoxVector Validation

Validation is task-specific. A method cannot be treated as inferentially validated merely because it is implemented, tested, or reported in research.

Required progression:

1. Freeze the operational method definition.
2. Define target task and population.
3. Establish speaker-disjoint development and evaluation partitions.
4. Document sampling, class balance, recording conditions, and exclusions.
5. Evaluate out of sample.
6. Report uncertainty, errors, calibration where appropriate, and robustness.
7. Test abstention and reliability behavior.
8. Replicate externally when feasible.
9. Record the resulting status in the validation registry.

Current VoxVector deception classification is not validated and remains fail-closed.
